Jason Snell at [Six Colors](https://sixcolors.com/link/2026/10/lex-authors-the-apps-but-claude-writes-the-code/) is revisiting a point he made back in June about AI coding assistants, and it's worth sitting with: the hard part of building software was never really the typing.

His framing is that you still need a human brain for "being creative, solving problems, and making decisions." Which sounds obvious until you realize how much of the last two decades of tech discourse has been about learning to code, as if syntax mastery was the gatekeeper skill. Turns out it wasn't. The gatekeeper skill was knowing *what* to build, *why* it should work a certain way, and *when* to kill a feature that isn't working. The code was just the invoice.

This maps directly onto what's happening with Apple's own development tools. Xcode's predictive code completion is table stakes now. GitHub Copilot writes whole functions. Anthropic's Claude can scaffold an entire app if you describe it clearly enough. But none of them can tell you that your three-tab navigation is confusing, or that your onboarding flow assumes too much knowledge, or that you're solving a problem nobody actually has. You still need product sense. You still need taste. You still need to understand people.

The interesting shift is that "product manager" and "developer" are collapsing into the same role for a lot of small projects. If you can clearly articulate what you want and validate that it works, the AI will write the Swift. That's not replacing developers—it's just revealing that the best developers were always the ones who understood the product, not the ones who had the most Stack Overflow rep.

Apple's entire design philosophy has always been about this kind of authorship: someone with a vision using tools to execute it. The tool is just more powerful now, and the vision matters more than ever.
