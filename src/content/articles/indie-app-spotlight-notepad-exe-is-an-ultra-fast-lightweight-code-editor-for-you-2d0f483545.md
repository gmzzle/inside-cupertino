[9to5Mac](https://9to5mac.com/2026/08/15/indie-app-spotlight-notepad-exe-is-an-ultra-fast-lightweight-code-editor-for-your-mac/) covered a new Mac code editor called Notepad.exe that does something radical: it lets you start typing code immediately without setting up a project first. Which sounds like table stakes until you remember that VS Code makes you create a folder, open that folder, dismiss seventeen extension recommendations, and wait for TypeScript to index the universe before you can write three lines of JavaScript.

The pitch here is speed and simplicity. You open the app, you get a blank file, you write. If you need to save it as a project later, fine. But the default state is just a text editor that understands syntax highlighting and doesn't demand you architect your entire workflow upfront. It's the difference between grabbing a napkin to sketch an idea versus getting out the drafting table and T-square.

This matters more than it sounds like it should. Heavyweight editors have gotten so feature-rich that they've forgotten the scratch pad use case entirely. TextEdit is useless for code. Xcode is a joke for anything quick. VS Code is overkill and slow to launch. There's been a gap here for years, and developers have mostly just lived with it or kept Sublime Text around as a side piece. The fact that someone named their app Notepad.exe is both on-the-nose and kind of perfect—it's a direct callback to Windows' actually-just-a-text-editor that could open instantly and get out of your way.

The indie dev angle is relevant too. Apple's own developer tools have gotten more complex, not simpler, and the Mac App Store doesn't exactly surface scrappy utility apps like this. These tools have to find an audience through word of mouth, which means they either nail a specific pain point or die in obscurity. Notepad.exe seems to be betting that enough Mac developers are tired of waiting for Electron apps to spin up just to edit a config file.

Whether it sticks depends on execution—how fast it actually launches, whether the syntax highlighting is good enough, if it handles large files without choking. But the core idea is right: sometimes you just need to type some code without turning it into a whole thing first.
